**Gap.** #36's guard makes a split headline (acquittal on one charge + conviction on another in the same reporting) `classify()` → null, so the engine HOLDS instead of publishing a false single outcome. A conflict escalates; a split did not.

**Fix — additive, alert-only, cannot cause a publication.**
- `scripts/verdict.js`: new `isDecidedSplit()` — a split that is *asserted* (both signals present) and *not* hypothetical (clause-scoped `HYPOTHETICAL` guard next to each signal) or historical (whole-string `HISTORICAL`), so previews/explainers of a *possible* split never fire. `assess()` now tallies decided-split headlines by independent family (same family + copyKey dedupe as outcomes) and, when there is **no** publishable single consensus and **no** conflict, returns a new `status:'split'` at `SPLIT_MIN=2` independent families. Ordering is strict: **conflict → ready(clean ≥MIN) → split → watch → none**, so a split alert **never suppresses a real verdict** (a clean lesser-charge conviction by ≥3 families still publishes) and never invents an outcome (`split` carries no `outcome`).
