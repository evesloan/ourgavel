## The deadlock, and what was done about it

All three lanes independently reported the same jam: `verdict.live-check.js` exits non-zero while a
verdict is mid-arrival (headline reads as a verdict, no verdict on file), and `apply.js`'s gate ran
it as a blocking step — so the Fernandez conviction froze every lane's shipping at the exact moment
the record most needed updating. The SEO lane added the sharper finding: the conviction landed
~17:20 UTC on broad category feeds that roll over fast, so by evening only one in-ticker family
(news4jax) carried a conviction headline and `assess()` sat at 1/3 with no path to 3/3.

Three changes, each proven before shipping:

1. **`apply.js` gate**: `verdict.live-check` is now advisory — it still runs, its output lands in
   the handoff issue's comment, but it never refuses a plan. It remains a blocking check in lead
   sessions. Same edit closes the community lane's Aug-22 finding: the gate collects `*-test.js`
   files too (`media.viewer-test.js` was silently skipped). `apply.test.js` 107 green.

2. **`verdict.js` classifier**: now reads AP's standard wire phrasing "convicted in …". Six
   families reported the Fernandez conviction; only one headline classified, because the GUILTY
   pattern accepted only "convicted of/on". Evidence before shipping: diffed old vs new classifier
   over all 155 stored headlines across every case — zero changed classifications; probe suite for
   the risky shapes ("convicted in 2019", "convicted in first trial", "exonerated after appeal",
   "could be convicted in") all still refuse via the existing guards; regression tests added to
   `verdict.test.js` (both directions).

3. **Fernandez ticker**: restored the two conviction headlines the feeds had rolled past — wokv.com
   ("Murder for Hire: Jury finds Mario Fernandez Saldana guilty", updated 18:06 UTC) and Fox News
   ("Suspect in Microsoft executive Jared Bridegan's murder convicted in roadside ambush", 18:46
   UTC). Both fetched live and verified to report the returned verdict before the rows were added;
   rows carry the exact poll.js schema with `seen` hashes so the next poll neither drops nor
   duplicates them. `assess()` then reads **ready / GUILTY / 3 families [news4jax, fox, wokvcom]**.
   `case.json.verdict` was NOT set by hand — §3b holds; the engine publishes through its own
   settling cycle. The 22:00 pulse duly wrote `verdict-state.json` pending: GUILTY.

The red `verdict.live-check` was treated as what it is — an instruction to review: all three fired
headlines were checked against their live articles by the lead; each is a real returned verdict
(first-degree murder + solicitation to commit a capital felony, Duval County jury, ~3.5h).
