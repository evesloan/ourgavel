## Growth — the embed was broken, and the embed is the whole creator channel

AGENT.md: *improving a board is growth work*, and a scheduled run has no posting surface. The
board that gets embedded on somebody else's site is the highest-leverage version of that, so this
run tested the embed instead of admiring it.

**The finding.** Above the embed code, our board page promises a creator: *"Paste this anywhere
that accepts HTML. The board stays live: reader theories, new evidence and every update appear in
your embed automatically."* That was false on every embed of every case, since the feature shipped.

The freshness poll is `fetch('./board-data.json')`. `board-data.json` is written to
`cases/<slug>/board/`. The embed is served from `cases/<slug>/board/embed/` — one directory
deeper — and the client script is shared verbatim by both pages. So on an embed the poll resolved
to `cases/<slug>/board/embed/board-data.json`, which has never existed.

Consequences, worst last: a 404 and a console error every sixty seconds *in the creator's
readers' browsers, on the creator's own page*, swallowed by a bare `.catch(){}` so it never
surfaced on our side; and the "Load the latest →" toast could not fire in an embed, ever — the one
sentence we use to sell the thing. With the Clancy verdict expected within days, an embedded board
that cannot tell a reader it has moved on is the exact failure that matters most.

**Found by loading the real embed code in a real cross-origin page and watching the network.** It
is invisible in the source, invisible in a browser, and invisible to every other check we run.

**Fix:** the path is written per page — `../board-data.json` on the embed, `./board-data.json` on
the board. Six lines in `scripts/build.js`, five of them the comment explaining why. No data files,
no templates, no CSP hash change (`connect-src 'self'` already permits it; verified by fetching it
from inside the frame in a real browser).

**Good news, also tested rather than assumed:** the embed is *not* blocked from a third-party
origin (no `frame-ancestors` in the meta CSP, and GitHub Pages sends no `X-Frame-Options`); all 13
Clancy nodes and all 13 Murdaugh nodes render inside the frame; a card opens and shows its own
cited source link; the backlink home is present, correct and `rel="noopener"`; and a full gallery
page inside the frame makes **zero** requests to any host other than ours — a creator who embeds
us does not hand their readers to a third party. That last one is SECURITY.md's hotlinking rule
holding up under the one condition nobody had tested it in.

### `scripts/embed.test.js` — 134 assertions, six-for-six on mutation

Two halves, deliberately: **MUST HAND OUT** (the code on the board page is correct and
self-consistent, all five cases — absolute https src, screen-reader title, lazy, inert markup, a
freshness poll that resolves to a file that exists and agrees with the serial baked into the page,
a backlink to the full board, canonical pointing at the board not itself, nothing hotlinked) and
**MUST WORK EMBEDDED** (a real Chromium page on `localhost:8909` framing `127.0.0.1:8908`, so the
iframe is genuinely cross-origin). It reads the embed code out of the board page rather than
writing its own — it tests the string a creator actually copies.

The live promise is exercised, not waited for: fetch the poll from inside the frame, assert 200 and
the expected serial, run a rebuild, fetch again, and assert the frame can now see a *different*
serial. That is "Load the latest can fire", proved end to end in about a second instead of sixty.

Mutations, all caught: the original defect restored; `loading="lazy"` dropped from the iframe;
the serial frozen so no update is ever visible; `rel="noopener"` dropped from the backlink; the
embed canonicalised to itself; one board node dropped from the render. (Two earlier mutation
attempts silently hit the wrong string — a photo `img`, and a `rel` that another link on the page
also carried. Both were *my* errors, not passes: the second one exposed a genuinely weak assertion,
which is now anchored to `<a class="eb" ...>` specifically.)
