## Development — ONE piece: ticker relevance, the Duval-County over-match (community 14:41)
**Defect (measured, not imagined):** Gardner's ticker carried row 0 —
"'Two Dope Chicks Who Give A Care' organization pencils in year-round support for 4 Duval County
schools" (News4JAX, positively-jax) — a charity story that entered the record because it matched the
bare geographic keyword **"duval county"**. Community flagged it §5-clean but off-topic ticker noise
and handed it to dev as a ticker-relevance item.

**Root cause:** `poll.js` ingest matched on `CASE.keywords.some(k => title.includes(k))`. A county
name is a legitimate keyword *with* a case-specific term and pure noise *without* one — every
Jacksonville school-board / weather / blotter story shares the county — so a bare "duval county" hit
was sufficient on its own to pull a row.

**Fix (structural, subtractive, opt-in, generalises):**
- `canonical.js` — new pure `matchesCaseKeywords(headline, keywords, geoKeywords)`: a headline is a
  case match only when it hits at least one **STRONG** (non-geo) keyword. A keyword also listed in
  `geoKeywords` corroborates but never matches alone. A case with no `geoKeywords` is byte-for-byte
  the old `keywords.some(includes)` — every other case unchanged. It can only DECLINE a too-thin
  match, never suppress a row that also names the defendant, so it cannot cost real coverage.
- `poll.js` — ingest gate now `matchesCaseKeywords(it.title, CASE.keywords, CASE.geoKeywords)`;
  removed the now-dead lowercased `kws`. The #22 `isOffTopic` exclude-veto is untouched.
- `data/cases/shanna-gardner/case.json` — declares `geoKeywords: ["duval county"]` ("duval county"
  stays in `keywords` so it still corroborates a real Gardner row). This blocks **re-ingest** at the
  door — the durable partner to scrubbing the stored row, so the fix survives the next poll.
- `data/cases/shanna-gardner/ticker.json` — scrubbed the one charity row (4 → 3 rows, all Gardner).
- `canonical.test.js` — behavioural tests against the real headlines (the charity row is declined,
  the three real Gardner rows still match, strong+geo together still matches, another geo-only row is
  declined, no-geoKeywords behaviour is unchanged, case-insensitive, empty/blank/null never throw)
  plus a live-record assertion (row gone from ticker, geoKeyword declared) and a mutation-checked
  wiring assertion on the poll.js call.
