## E13 — robots.txt was being used for canonicalisation, and that is not a thing it does

`build.js` wrote `Disallow: /*/board/embed/` into robots.txt under the comment "index the board
instead". Every embed already carries `<link rel="canonical">` to its own board, and all five are
correct. But Google cannot read a canonical on a URL it is not allowed to crawl. From Google's own
documentation:

> Don't use the robots.txt file for canonicalization purposes. Google may still index URLs that are
> disallowed in robots.txt without their content.

and, on the same mechanism:

> If the page is blocked by a robots.txt file or the crawler can't access the page, the crawler will
> never see the noindex rule, and the page can still appear in search results, for example if other
> pages link to it.

So the block did the opposite of what its comment claimed. The embed URL could still be indexed
with no content attached, which is the worse of the two outcomes, while the canonical that would
have folded it into the board went unread.

The cost lands on the one channel we have. An embed is what a creator pastes into their own page.
That is our only inbound link surface, and the single backlink home inside each embed was invisible
to a crawler forbidden to fetch the file. Measured on the built output before the change: each
embed carries exactly one link to `ourgavel.com`, and it goes to that case's board. Patch 0f turns
three dead buttons in the embed into real deep links back to the board. All of those would have
been invisible too.

**Fix:** delete the Disallow. Keep the canonical, which is the mechanism for this and is already in
place. Five more crawlable pages on a 34-page site is not a crawl-budget question. The sitemap
still does not list the embeds — a canonicalised duplicate should be reachable, not advertised.

*Hypothesis:* once a creator embeds a board, the embed consolidates into the board instead of
sitting in the index as a content-less URL, and the links inside it reach the board pages.
*Measure:* Search Console → Pages. Today the five embed URLs should sit under "Blocked by
robots.txt"; after this they should move to "Alternate page with proper canonical tag", and Links →
Internal should start counting the embed's link home.
*Kill criterion:* if Google indexes an embed URL in its own right rather than folding it into the
board, the canonical is not being honoured and these pages need `noindex` and a crawl allow
instead. That would be visible in Search Console as an embed URL indexed.
