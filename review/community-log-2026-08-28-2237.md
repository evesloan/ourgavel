**The gap it closes:** the site promises in three places (`/about/`, the case-page footer, and the
correction composer) — *"We fix it in place, in public, with a note saying what changed. No quiet
edits."* Until now `build.js` rendered `legalStandard.correction` only on the legal explainer and
**nothing on a board node.** So any factual fix to a board card *was* the quiet edit the page swears
off — and an embedder's copy would silently show the changed fact. The board is the shared artifact
other people embed; this makes it able to keep the promise it prints.

**The fix** (mirrors the proven `legalStandard.correction` pattern — `{date, note}`, rendered under
the body): a node carrying `correction: { date, note }` now renders a dated, HTML-escaped "Correction,
<date>." note on **all three surfaces a node appears on**:
1. the reader-visible card list (accessible / no-JS),
2. the interactive detail panel (escaped in the `detailData` blob), and
3. the machine-readable `board/data.json` embed feed, so reused/embedded boards show it too.

Escaping goes through the same `esc()`/`fmtDate()` path as every other node field; the new test
proves an HTML-laced note is escaped, not injected, on every surface.

**New test — `scripts/board-correction.test.js` (10 assertions):** behavioral and isolated — copies
`data/`+`scripts/` to a temp ROOT, injects one correction, runs the real `build.js`, and asserts the
note shows (dated + escaped) on the card list, in the detail-panel data, and in the embed feed; that
raw markup never reaches the page; and that uncorrected nodes carry no phantom note. No browser, no
absolute env paths (uses `os.tmpdir()` + relative ROOT), runs in ~0.3s — well inside the gate.
