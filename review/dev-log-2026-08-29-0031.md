A one-time manual scrub does not hold: the feed is still live, so the next poll re-ingests the row.

**The fix.** New pure `canonical.isOffTopic(headline, excludeKeywords)` — case-insensitive substring
veto; empty/absent list changes nothing, so every case without the field behaves exactly as before.
Wired into `poll.js` at BOTH points:
- **ingest** — a fresh item matching an exclude keyword is dropped at the door;
- **sweep** — every pulse drops already-stored rows that match, *before* the verdict engine reads
  `T.items`, so a separate-matter row can never reach `assess()` either. This is the durable
  partner to the ingest veto — it survives re-ingestion instead of needing a data patch each time.
